1. The NVIDIA AI Software Stack (Bottom to Top)

The exam frequently asks about the role of each layer and the order of execution:

Layer 1

CUDA

Parallel computing platform; base OS/kernel layer for all GPU programming.

Layer 2

cuDNN & cuBLAS

GPU-accelerated deep learning primitives and BLAS linear algebra library.

Layer 3

Frameworks

PyTorch, TensorFlow, JAX; environment where neural networks are constructed.

Layer 4

TensorRT

Inference optimizer SDK; fuses layers, quantizes (FP8/INT8/FP16) for 2–5x lower latency.

Layer 5

NGC Catalog

Free public hub for optimized container images, pre-trained models, and Helm charts.

Layer 6

AI Enterprise

Enterprise management platform with production SLAs, VMware/Red Hat support.

DGX H100 System Architecture

  • • 8x H100 SXM5 GPUs: 640 GB total aggregate HBM3 memory.
  • • NVLink 4.0 + 4x NVSwitches: 900 GB/s bidirectional per GPU (3.6 TB/s aggregate per GPU).
  • • CPUs & Memory: Dual Intel Xeon Platinum CPUs, 2 TB DDR5 system memory.
  • • Networking: 8x ConnectX-7 high-speed ports (400 Gbps InfiniBand NDR or 100 GbE) for compute.
  • • Out-of-band BMC: 1x 1 GbE RJ45 dedicated management port (NOT for compute traffic).
  • • Power: ~10.2 kW max power consumption (requires 3-phase power delivery).

DCGM & Observability Cheat Sheet

  • • DCGM: Data Center GPU Manager for cluster monitoring, profiling, and health checks.
  • • SBE vs DBE: Single-Bit ECC errors (SBE) are correctable. Double-Bit ECC errors (DBE) are uncorrectable and indicate immediate hardware replacement.
  • • Thermal Throttling: Begins around ~83°C on modern Hopper/Ampere data center GPUs.
  • • Prometheus Export: Uses dcgm-exporter to export metrics into Grafana dashboards.
  • • Slurm vs K8s: Slurm is optimized for static HPC batch training; Kubernetes GPU Operator is standard for microservices and real-time inference serving.
